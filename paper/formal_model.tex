\noindent{\large\bfseries Formal model of the authority gate}

\paragraph{Setting.}
As in AuthMem-Bench, $H = \langle (x_i, r_i) \rangle_{i=1}^{n}$ is a role-labeled history, $q$
the later request, and $\Au \succ \At \succ \Un$ the labels. $\Act$ is the finite set of protected
actions. Each $a \in \Act$ has parameters $P_a$, each read from a slot key $\kappa_a(p)$ with a
declared value format. $\kappa_a$ is injective, and $s_a \in P_a \cup \{\bot\}$ names the
parameter identifying the object $a$ acts on, if any; the \emph{scope keys} are the keys
$\kappa_a(s_a)$, $s_a \neq \bot$, over all actions. Each message $x$ other than a system message
arrives on a \emph{channel} $\chi(x) \in \{\cU, \cT, \cX, \cA\}$. The channel is fixed by the role
of $x$ and, for a tool result, by the trust declared for the tool that produced it: $\cT$ for the
bank's own systems, $\cX$ for outside feeds and unknown tools. The text of $x$ never enters
$\chi$. Each channel has a \emph{ceiling} $\hat\ell(\cU) = \Au$, $\hat\ell(\cT) = \hat\ell(\cA) = \At$,
$\hat\ell(\cX) = \Un$. Records seeded from the bank's own books (the customer's accounts) are
created by code outside Definition~\ref{def:write}: channel $\cS$, label $\Au$, slots from their
fields, no requests (\texttt{system} in the code; unrelated to system messages).

\paragraph{Model calls.}
Every message and consolidated memory goes through slot extraction $E(x)$, which cannot affect
a label. A customer message is also asked two yes/no questions: $Q(x)$, whether the customer is quoting someone else, and $R(x)$, whether they are
declining or deferring. An answer counts only if its first word is yes or no and the other word
does not occur as a word; anything else is $\bot$. $L(x)$ selects actions from the closed set $\Act$: only items that are exactly action names count,
and any ``none'' gives $\emptyset$. \emph{No answer is assumed correct.} No model is asked anything about a tool result or
the agent's own text.

\begin{definition}[Write]\label{def:write}
Each message $x$ is stored with a label $\ell$ and a request list $\Req$:
\[
(\ell, \Req) =
\begin{cases}
(\Un, \emptyset) & \chi = \cX, \text{ or } \chi = \cU \wedge Q(x) \neq \no;\\
(\Au, \emptyset) & \chi = \cU \wedge Q(x) = \no \wedge R(x) \neq \no;\\
(\Au, L(x))      & \chi = \cU \wedge Q(x) = \no \wedge R(x) = \no;\\
(\At, \emptyset) & \chi \in \{\cT, \cA\}.
\end{cases}
\]
So $\ell \preceq \hat\ell(\chi)$ always: content can lower a label (a quotation), never raise it; a
grant a bank system returns is $\At$.
The record's slots $S$ are the pairs of $E(x)$ whose key is in the closed key set, whose value
fits the key's format, and whose value is a case-insensitive substring of $x$. Values are compared
as exact strings. For $a \in \Req$, $\Arg(a)$ names parameter $p$ with $v$ iff $v$ is the only
value in $S$ for $\kappa_a(p)$. The record's object $o$ is the single value in $S$ under any scope
key; it is $\bot$ if there is none, and a marker matching no value if there are several (fails
closed). Consolidated memories are the agent's own writing and are stored with $\chi = \cA$. The
store refuses an $\Au$ record on any channel but $\cU$, or with no channel at all. In Module B the
benchmark supplies the focal record: the quote that introduced the claim, its carrier's channel
($\cU$ in $H^{+}$) and a slot passing the filter above; $\ell$ and $\Req$ come from the rule. Module C
derives the channel from its own capture, end to end.
\end{definition}

\paragraph{Order.} All of $H$, then $q$ (on $\cU$), is written before the agent acts. During the
action stage the only write spends a license (below); no write ever changes a label.

\begin{definition}[Gate]
Let $M^{\Au}$ be the $\Au$ records of the store $M$, and $M_k$ the records with slot key $k$. A call
to $a$ carries optional proposals $\pi(p)$ from the agent; $x \simeq y$ compares values ignoring
case and whitespace, and a matched value is taken in the record's form. A call is decided from $M$:
\begin{enumerate}
\item \emph{License.} Let $C = \{ r \in M^{\Au} : a \in \Req(r) \}$; if empty, refuse. If
  $s_a \neq \bot$, let $O$ be the objects the requests of $C$ name, or if none, the values under
  $\kappa_a(s_a)$ on $M^{\Au}$. Then $o^*$ is the one in $O$ that is $\simeq \pi(s_a)$ if proposed,
  else the only one; otherwise refuse. Also refuse if a non-$\Au$ record on $\cU$ has another
  value under $\kappa_a(s_a)$. Let $\Lambda = \{ r \in C : s_a = \bot \vee o(r) \in \{\bot, o^*\} \}$;
  if empty, refuse. A refusal asks the customer nothing.
\item \emph{Arguments.} $s_a$ is bound to $o^*$. For each other $p$ with $k = \kappa_a(p)$, let $N$
  be the values the records of $\Lambda$ name for $p$, and $A = \vals(M_k \cap M^{\Au})$. (i) If
  $N \neq \emptyset$, bind the one in $N$ that is $\simeq \pi(p)$ if proposed, else the only one;
  otherwise $p$ is ambiguous. (ii) Else if $\pi(p) \simeq v \in A$, bind $v$. (iii) Else if $\pi(p)$ is
  proposed, $p$ is ambiguous between $\pi(p)$ and $A$, or blocked if $A = \emptyset$ (source ``the
  assistant'' if no record carries it). (iv) Else, with $V = \vals(M_k)$: missing if $V = \emptyset$,
  ambiguous if $|V| > 1$; if $V = \{v\}$, bind $v$ when some record of $M_k$ is $\Au$, else blocked.
  A bound value is ambiguous instead if a non-$\Au$ record on $\cU$ has another value under $k$.
\item \emph{Customer.} If a parameter is not bound, the gate asks the customer, within the same
  call, through an interface $K$ the harness provides: missing values are typed in and must fit
  their format; ambiguous ones are chosen from buttons naming each value's least trusted source;
  each blocked value, shown with that source, is accepted, rejected or replaced; then the whole
  call gets a final yes/no. Any unanswered or rejected step, or no $K$, stops the call. Answers
  are used for this call only and never written.
\item \emph{Execution.} Execute with the bound and answered values, then remove $a$ from $\Req$ of
  every record in $\Lambda$.
\end{enumerate}
The agent supplies $a$ and $\pi$; it has no access to $K$. A proposal selects, never authorizes.
\end{definition}

\begin{assumption}[Integration]\label{as:int}
(i) Roles and the producing tool of a message cannot be forged by content. (ii) A tool declared
trusted is the bank's own system. (iii) $K$ is operated by the customer and shows exactly what the
gate renders; no measured run attaches it.
\end{assumption}

\begin{theorem} For all model answers and every agent behaviour:
\begin{enumerate}
\item \emph{Provenance.} A record is $\Au$ only if it is on $\cU$ with $Q = \no$, or seeded from the
  books; it requests $a$ only if also $R = \no$ and $L$ listed $a$. Nothing on $\cT$, $\cX$, $\cA$,
  no consolidated memory and no grant is ever $\Au$.
\item \emph{Soundness.} If $a$ executes without the customer, some $\Au$ record requests $a$, and
  each argument is named by such a record, or is carried by an $\Au$ record under its slot (the
  only value on record there, or the one the agent proposed), or, for the object, is among the
  values under its key on $\Au$ records. Either way it is a substring of an $\Au$ message or a
  seeded value.
\item \emph{Monotonicity.} Without the customer, adding any record with $\ell \neq \Au$ to $M$
  never makes a call execute and never changes the arguments of an executing one.
\item \emph{Non-interference.} The executed arguments are a function of $M$, $a$, $\pi$ and the
  customer's answers. Text in the agent's context reaches the gate only through $a$ and $\pi$,
  and a proposal only selects among values $\Au$ records carry, or is put to the customer.
\item \emph{The customer step is local.} Each argument satisfies (2) or was typed, chosen or
  accepted by the customer, who saw its source and the whole call. It cannot bypass the license.
\item \emph{One request, one execution.} After $a$ executes, no record of $\Lambda$ requests $a$; a
  further call needs a new request.
\end{enumerate}
\end{theorem}
\begin{proof}[Proof sketch]
(1) Definition~\ref{def:write} and the store's refusal. (2) Steps 1--2 and the substring filter.
(3) $M^{\Au}$, hence $\Lambda$, $O$ and $A$, is unchanged. (4) The gate reads only $M$, $\pi$ and $K$.
(5) Step 3 writes nothing, and a refused license never reaches it. (6) Step 4.
\end{proof}

\paragraph{Consequence for authority pairs.}
No measured run attaches $K$, so (2)--(3) cover every measured execution. In a validated core or
multi-argument pair nothing is seeded and $v^*$ occurs (ignoring case) in no message of $H^{-}$ but
the carrier; so by (2) an $H^{-}$ execution needs the carrier to be $\Au$, which (1) rules out for a
carrier on $\cX$, $\cA$ (R2F, P2R, MIX, R2P, S2D) or $\cT$ (C2O, O2I), whatever the agent proposes.
Only in Q2D (the customer quotes a third party) does a measured result depend on a model, through
$Q$; in general, only through $Q$, $R$ and $L$ on customer messages. A consolidated memory is on
$\cA$, so its implied uses $\widehat{\Pi}(m)$ never include licensing or binding.

\paragraph{Departures and limitations.}
Beyond the paper: a quoting customer is $\Un$; a bank system's
result is $\At$, a grant included. (a) No time or withdrawal: a later refusal does not cancel an earlier request, and an unused request never lapses (EAL-Bench's threat model, arXiv:2609.01836); two identical requests
yield one execution. (b) Values in a refusal are $\Au$ slots. (c) The substring filter ignores token
boundaries. (d) Without $K$ an ambiguous value is refused. (e) A compromised agent can raise one
customer dialogue per licensed call.
