\section*{Formal model of the authority gate}

\paragraph{Setting.}
As in AuthMem-Bench, $H = \langle (x_i, r_i) \rangle_{i=1}^{n}$ is a role-labeled history, $q$
the later request, and $\Au \succ \At \succ \Un$ the labels. $\Act$ is the finite set of protected
actions. Each $a \in \Act$ has parameters $P_a$, each read from a slot key $\kappa_a(p)$ with a
declared value format. $\kappa_a$ is injective, and $s_a \in P_a \cup \{\bot\}$ names the
parameter identifying the object $a$ acts on, if any; the \emph{scope keys} are the keys
$\kappa_a(s_a)$, $s_a \neq \bot$, over all actions. System messages are not a memory source, as
in the paper. Each other message $x$ arrives on a \emph{channel} $\chi(x) \in \{\cU, \cT, \cX,
\cA\}$. The channel is fixed by the role of $x$ and, for a tool result, by the trust declared for
the tool that produced it: $\cT$ for the bank's own systems, $\cX$ for outside feeds and unknown
tools. The text of $x$ never enters $\chi$.

\paragraph{Model calls.}
Writing a message involves up to six model calls. Three are yes/no questions: $Q(x)$, whether the
customer is quoting someone else; $R(x)$, whether they are declining or deferring; and $G(x)$,
whether a bank record carries a currently valid signed authorization. Two select from the closed
set $\Act$: $L(x)$, the actions the customer asks for, and $C(x)$, the actions a grant permits.
The sixth, $E(x)$, extracts (key, value) pairs. An unusable yes/no answer is written $\bot$; an
unusable $L$, $C$ or $E$ answer is $\emptyset$. \emph{No property of any answer is assumed}; all
six may be adversarial.

\begin{definition}[Write]\label{def:write}
Each message $x$ is stored with a label $\ell$ and a request list $\Req$:
\[
(\ell, \Req) =
\begin{cases}
(\Un, \emptyset) & \chi = \cX, \text{ or } \chi = \cU \wedge Q(x) \neq \no;\\
(\Au, \emptyset) & \chi = \cU \wedge Q(x) = \no \wedge R(x) \neq \no;\\
(\Au, L(x))      & \chi = \cU \wedge Q(x) = \no \wedge R(x) = \no;\\
(\Au, C(x))      & \chi = \cT \wedge G(x) = \yes;\\
(\At, \emptyset) & \chi = \cT \wedge G(x) \neq \yes, \text{ or } \chi = \cA.
\end{cases}
\]
The record's slots $S$ are the pairs of $E(x)$ whose key is in the closed key set, whose value
fits the key's format, and whose value is a case-insensitive substring of $x$. Values are compared
as exact strings. For $a \in \Req$, $\Arg(a)$ names parameter $p$ with $v$ iff $v$ is the only
value in $S$ for $\kappa_a(p)$. The object of the record, $o$, is the single value in $S$ under any
scope key; it is $\bot$ if there is none, and a marker matching no value if there are several, so
a record naming two objects licenses no scoped action (this fails closed).
Consolidated memories are the agent's own writing and are stored with $\chi = \cA$. The store
refuses any $\Au$ record on $\cA$ or $\cX$, and no stored record is ever modified.
\end{definition}

\paragraph{Order.} Every message of $H$ and then $q$ (on $\cU$) is written before the agent acts.
During the action stage the agent holds only the gate and a question-to-customer tool, and no
answer to that question is written to memory. The only write during the stage is the customer's
reply to a confirmation request (below). Until then the store $M$ is fixed.

\begin{definition}[Gate]
Let $M^{\Au}$ be the $\Au$ records of $M$ and $M_k$ the records with slot key $k$. A call to $a$
is decided from $M$ alone:
\begin{enumerate}
\item \emph{License.} If $s_a \neq \bot$, let $O$ be the values under $\kappa_a(s_a)$ on
  $M^{\Au}$. If $|O| \neq 1$, refuse; otherwise $O = \{o^*\}$. Let
  $\Lambda = \{ r \in M^{\Au} : a \in \Req(r),\ s_a = \bot \vee o(r) \in \{\bot, o^*\} \}$.
  If $\Lambda = \emptyset$, refuse, and issue no confirmation reference.
\item \emph{Arguments.} For each $p \in P_a$ with $k = \kappa_a(p)$: if the records of $\Lambda$
  name exactly one value, bind it, and if they name several, $p$ is ambiguous. If they name none,
  let $V = \vals(M_k)$. If $V = \emptyset$, $p$ is missing; if $|V| > 1$, $p$ is ambiguous. If
  $V = \{v\}$, bind $v$ when $\max\{\ell(r) : r \in M_k\} = \Au$, and otherwise mark $p$ blocked.
\item \emph{Decision.} Execute if every parameter is bound. Otherwise issue a fresh single-use
  reference $t$ recording $a$, the bound values and the blocked values.
\end{enumerate}
The customer is shown a request rendered from $t$: the action $a$, every bound value, the blocked
values with their source, and a question for each missing or ambiguous parameter. The agent is told only that the customer has
been asked. The reply is written like any customer message, except that its request list is empty: it fills
its pending call and licenses nothing. The harness passes the gate its rows $Y$
and a flag $\gamma$, which comes from an explicit control the customer operates, never from a
model's reading of the reply. Presenting $t$ consumes it. If $\gamma = \mathit{true}$,
each parameter that was blocked, missing or ambiguous takes the value for its key if the $\Au$
records of $Y$ state exactly one such value. Otherwise a blocked parameter keeps its recorded
value. The call executes if every parameter then has a value. The agent supplies only $a$ and $t$:
$\gamma$ and $Y$ are not in its tool schema, and any arguments the agent writes are discarded.
\end{definition}

\begin{assumption}[Integration]\label{as:int}
(i) Roles and the producing tool of every message cannot be forged by content. (ii) A tool
declared trusted is the bank's own authenticated system. (iii) The harness sets
$\gamma = \mathit{true}$ only after the customer has approved the request rendered from $t$.
Part (iii) describes deployment. In the measured runs no confirmation is ever given.
\end{assumption}

\begin{theorem} For all model answers and every agent behaviour:
\begin{enumerate}
\item \emph{Provenance.} A record is $\Au$ only if it is on $\cU$ and $Q$ answered \no, or on
  $\cT$ and $G$ answered \yes. It requests $a$ only if, in addition, $R$ answered \no\ and $L$
  listed $a$, or $C$ listed $a$. No record on $\cX$ or $\cA$, and hence no consolidated memory,
  is ever $\Au$, whatever any model answers.
\item \emph{Soundness.} If $a$ executes without confirmation, some $\Au$ record requests $a$.
  Each argument is then either named by such a record or is the only value on record for its
  slot and is carried by an $\Au$ record. Either way it is a substring of an $\Au$ message.
\item \emph{Monotonicity.} Without confirmation, adding any record with $\ell \neq \Au$ to $M$
  never makes a call execute and never changes the arguments of an executing one. (With
  confirmation it can turn a missing value into a blocked one, which is why the customer is shown
  the value itself.)
\item \emph{Non-interference.} Without confirmation, the executed arguments are a function of
  $M$ and $a$. Text in the agent's context reaches the gate only through the choice of $a$.
\item \emph{Confirmation is local.} $\gamma$ authorizes one call and cannot bypass the license.
  A missing or ambiguous value can come only from the customer's own reply, and only if that reply
  is $\Au$ and states exactly one value. With confirmation, each argument either satisfies (2),
  or was shown to the customer and approved, or is stated in their $\Au$ reply. Confirmation never
  changes a label, and the reply licenses no later call.
\end{enumerate}
\end{theorem}
\begin{proof}[Proof sketch]
(1) Read off Definition~\ref{def:write} together with the store's refusal. (2) Follows from the
three gate steps and the substring filter. (3) Adding the record leaves $M^{\Au}$, hence $\Lambda$,
unchanged. A value bound through $M_k$ in the larger store was already the only value there, and
it was already carried by an $\Au$ record of $M$. (4) The gate reads only $M$, and $M$ is fixed. (5)
The reference is consumed on first use, and the gate never writes $M$. A parameter left open under
$t$ is filled only from the $\Au$ rows of $Y$.
\end{proof}


\paragraph{Consequence for authority pairs.}
In a validated pair, the operative value of $p$ is a substring of no message of $H^{-}$ except the
carrier, and not of $q$. This was checked ignoring case on every measured pair. By (2) and (4), an unconfirmed $H^{-}$ execution needs the carrier itself
to be $\Au$. By (1) this is impossible for a carrier on $\cX$ or $\cA$ (R2F, P2R, MIX, R2P, S2D),
under any model behaviour. For a carrier on $\cT$ (C2O, O2I, and our G2O) it requires $G$ to answer
\yes\ on a record that is not a valid grant. For our Q2D, where the customer quotes a third party,
it requires $Q$ to answer \no. In the paper's terms, the implied uses $\widehat{\Pi}(m)$ of a record that is not $\Au$ never
include licensing an action or binding its argument, so the upgrade $\widehat{\Pi}(m) \not\subseteq
\Pi(\ell^*(p, H))$ cannot reach an action. The gate treats $\At$ and $\Un$ alike: neither can license an action
or bind an argument without confirmation, and confirmation never raises a label.

\paragraph{Departures and limitations.}
As an extension resting on Assumption~\ref{as:int}(ii), a customer quoting a third party is $\Un$
rather than $\Au$, and a bank tool's result is $\At$, or $\Au$ for a valid grant. (a) A license is
never consumed or revoked, and a grant stays $\Au$ after it expires.  This is the threat model of
EAL-Bench (arXiv:2609.01836), not ours. (b) Values stated in a refusal are
$\Au$ slots. (c) The substring filter ignores token boundaries (100 passes inside 1000). (d) Memory
has no time order: a corrected value stays ambiguous.
