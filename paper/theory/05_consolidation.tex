\section{Consolidation and forgetting}\label{sec:consolidation}

A consolidator rewrites memory: it summarises, merges and drops records. Its output is the agent's
own writing, so it lies on $\cA$ with ceiling $\At$ (Theorem~\ref{thm:ceiling}). Code, not the
agent, may attach \emph{carried} side information to a consolidated record, such as the labels,
requests and objects of the records it came from. That is how channel information survives
consolidation without being reconstructed afterwards.

\begin{proposition}[Consolidated text cannot license]\label{prop:consolidated}
Without carried side information, no consolidated record is $\Au$. $G$ reading only consolidated
memory never executes without the customer. It is sound, and it has zero utility on every
operation that needs a licence or a bound argument.
\end{proposition}
\begin{proof}
The ceiling of $\cA$ is $\At$, and every execution of $G$ without the customer needs an $\Au$
record.
\end{proof}

\begin{theorem}[One bit per value]\label{thm:bits}
Fix $n$ keys $k_1, \dots, k_n$ and values $v_1, \dots, v_n$. For $S \subseteq [n]$, let $h_S$ be the
history in which $v_i$ is asserted under $k_i$ by the customer in own voice if $i \in S$, and by an
outside feed otherwise, in the same wording. A consolidator that keeps every value but not its
source writes the same text for all $2^n$ histories. Any representation that is sound and misses
no permitted operation on these histories and their continuations must separate all $2^n$ of them.
So it must carry at least $n$ bits beyond the text in the worst case, and $H(S)$ bits on average.
\end{theorem}
\begin{proof}
For $S \neq S'$ pick $i$ in their symmetric difference. Then $\st_{k_i}$ is $v_i$ on one side and
$\bot$ on the other, and by Theorem~\ref{thm:exact} the two histories are not equivalent.
$2^n$ distinct memories that share the same text need $n$ bits outside it, and a uniquely
decodable encoding needs $H(S)$ bits on average.
\end{proof}

The carried label of the formal model is one of three values per record, $\log_2 3$ bits, so it is
within a constant factor of this bound. It must be written by code: by
Theorem~\ref{thm:ceiling}, the agent cannot write it into the text.

\subsection*{Which losses are safe}

A memory that is smaller than the canonical state (Corollary~\ref{cor:size}) must lose something.
The question is which losses can only cost utility and never safety.

\begin{definition}[Safe replacement]
A state $s'$ is a \emph{safe replacement} for the true state $s$ if, for every continuation that
executes only what $s'$ permits, $\Perm(s' u, o) = 1$ implies $\Perm(s u, o) = 1$. That is, a system
that remembers $s'$ in place of $s$ never executes anything $s$ forbids.
\end{definition}

\begin{theorem}[Safe forgetting leaves a mark]\label{thm:safe}\label{thm:tombstone}
$s'$ is a safe replacement for $s$ if and only if, for every action $a$, one of the following holds:
\begin{enumerate}
\item[(1)] $\rho'_a = \mathsf{blocked}$;
\item[(2)] $\rho_a$ is bare and $\rho'_a = \mathsf{absent}$, and every key $a$ reads satisfies (3);
\item[(3)] $\rho'_a = \rho_a$, and every key $k$ that $a$ reads has $\st'_k \in \{\st_k, \conflict\}$.
\end{enumerate}
Keys read only by blocked actions are unconstrained. In words, exactly three losses are safe:
\begin{itemize}
\item mark a key \emph{contested};
\item mark an action \emph{blocked};
\item drop a request that named nothing.
\end{itemize}
Forgetting a value ($v \mapsto \bot$), resolving a conflict ($\conflict \mapsto v$), changing a
value, and dropping or trimming a request that named something are each unsafe for some future.
\end{theorem}
\begin{proof}
\emph{If.} A blocked action is never permitted. A dropped bare request contributes nothing to
later merges (Theorem~\ref{thm:exact}(b)), so before a new request it permits nothing, and after
one the two states agree. For a key with $\st'_k = \conflict$, the key stays $\conflict$, since
$\conflict$ is absorbing, and permits nothing through that key. A key with $\st'_k = \st_k$ evolves
identically. The request states evolve identically, because they do not depend on keys, and the
executions are the same events on both sides. So whenever $s'u$ permits $o$, every key it reads
carries the same value in $su$, and $su$ permits $o$.

\emph{Only if.} For each violation, a continuation makes $s'$ permit what $s$ forbids.
\begin{itemize}
\item $\st'_k = v$ against $\st_k \in \{\bot, \conflict, v'\}$: request a reader of $k$ naming
  everything else.
\item $\st'_k = \bot$ against $\st_k = v$: first assert a fresh $w$, which gives $w$ against
  $\conflict$.
\item $\rho'_a$ drops or changes a named value or object: a request naming a fresh value there
  leaves $s'$ unblocked and blocks $s$.
\item $\rho'_a$ invents one: $s'$ binds it while $s$ reads a key that does not hold it.
\item $\rho'_a$ unblocks what $\rho_a$ blocks: any consistent request is permitted by $s'$ only.
\end{itemize}
Where the request state names the parameter to be read, one permitted execution first resets
both sides. That execution is permitted by $s'$, and if $s$ forbids it, it is already a
violation.
\end{proof}

\begin{corollary}[Silent forgetting is unsafe]
A consolidator that drops a value or a correction, or keeps one of two contested values, is not
merely less useful. It is unsafe for some future. Example~\ref{ex:correction} with the correction
dropped leaves X alone in memory while the customer's state is $\conflict$, and $G$ pays X. The
gate's veto on lowered customer words (Proposition~\ref{prop:lower}) applies this theorem: demoted
words still mark the key.
\end{corollary}

\begin{corollary}[Memory under a budget]
A safe memory smaller than the canonical state must lose information through marks. Its utility
loss is the probability that a later operation needs a marked component. Under a budget, the best
safe memory marks the components least likely to be needed. Every other way of fitting the budget
is unsafe.
\end{corollary}

\paragraph{Link to the experiment.} Theorems~\ref{thm:bits} and~\ref{thm:safe} make testable
predictions about real consolidators:
\begin{itemize}
\item whether they keep the source of each value (Module~A's judge measures this);
\item whether they forget contested values and corrections silently or with a mark.
\end{itemize}
The second needs correction pairs, which the suites do not have yet.
