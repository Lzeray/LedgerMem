\section{Consolidation and forgetting}\label{sec:consolidation}

A consolidator rewrites memory: it summarises, merges and drops records. Its output is the agent's
own writing, so it lies on $\cA$ with ceiling $\At$ (Theorem~\ref{thm:ceiling}). Code, not the
agent, may attach \emph{carried} side information to a consolidated record, such as the labels,
requests and objects of the records it came from. That is how channel information survives
consolidation without being reconstructed afterwards.

\begin{proposition}[Consolidated text cannot license]\label{prop:consolidated}
Without carried side information, no consolidated record is $\Au$. $G$ reading only consolidated
memory never executes without the customer. It is sound, and it has zero utility on every
operation that needs a licence or a bound argument.
\end{proposition}
\begin{proof}
The ceiling of $\cA$ is $\At$, and every execution of $G$ without the customer needs an $\Au$
record.
\end{proof}

\begin{theorem}[One bit per value]\label{thm:bits}
Fix $n$ keys $k_1, \dots, k_n$ and values $v_1, \dots, v_n$. For $S \subseteq [n]$, let $h_S$ be the
history in which $v_i$ is asserted under $k_i$ by the customer in own voice if $i \in S$, and by an
outside feed otherwise, in the same wording. A consolidator that keeps every value but not its
source writes the same text for all $2^n$ histories. Any representation that is sound and misses
no permitted operation on these histories and their continuations must separate all $2^n$ of them.
So it must carry at least $n$ bits beyond the text in the worst case, and $H(S)$ bits on average.
\end{theorem}
\begin{proof}
For $S \neq S'$ pick $i$ in their symmetric difference. Then $\st_{k_i}$ is $v_i$ on one side and
$\bot$ on the other, and by Theorem~\ref{thm:exact} the two histories are not equivalent.
$2^n$ distinct memories that share the same text need $n$ bits outside it, and a uniquely
decodable encoding needs $H(S)$ bits on average.
\end{proof}

The carried label of the formal model is one of three values per record, $\log_2 3$ bits, so it is
within a constant factor of this bound. It must be written by code: by
Theorem~\ref{thm:ceiling}, the agent cannot write it into the text.

\subsection*{Which losses are safe}

A memory that is smaller than the canonical state (Corollary~\ref{cor:size}) must lose something.
The question is which losses can only cost utility and never safety.

\begin{definition}[Safe replacement]
A memory state $s'$ is a \emph{safe replacement} for the true state $s$, written $s' \preceq s$, if
for every continuation $u$ that executes only what the memory permits,
$\Perm(s' u, o) = 1$ implies $\Perm(s u, o) = 1$. A system that remembers $s'$ in place of $s$ then
never executes anything $s$ forbids.
\end{definition}

\begin{lemma}[Safety is a simulation]\label{lem:simulation}
$\preceq$ is the greatest relation $R$ such that $s' \mathrel{R} s$ implies
$\Perm(s') \subseteq \Perm(s)$, and $\delta(s', e) \mathrel{R} \delta(s, e)$ for every event $e$ the
memory admits. An online memory, updated by the same events as the truth, is safe forever if and
only if it starts, and so remains, in this relation.
\end{lemma}
\begin{proof}
This is the standard greatest-fixed-point characterisation of a simulation preorder. Closure under
events is built in.
\end{proof}

The lemma is general. The content is in computing $\preceq$ for the authority semantics.

\begin{theorem}[Safe forgetting leaves a mark: static regime]\label{thm:safe}\label{thm:tombstone}
Up to the equivalence of Theorem~\ref{thm:exact}, $s' \preceq s$ if and only if, for every action
$a$, one of the following holds:
\begin{enumerate}
\item[(1)] $\rho'_a = \mathsf{blocked}$;
\item[(2)] $\rho_a$ is bare and $\rho'_a = \mathsf{absent}$, and every key $a$ reads satisfies (3);
\item[(3)] $\rho'_a = \rho_a$, and every key $k$ that $a$ reads has $\st'_k \in \{\st_k, \conflict\}$.
\end{enumerate}
Keys read only by blocked actions are unconstrained. In words, exactly three losses are safe:
\begin{itemize}
\item mark a key \emph{contested};
\item mark an action \emph{blocked};
\item drop a request that named nothing.
\end{itemize}
Forgetting a value ($v \mapsto \bot$), resolving a conflict ($\conflict \mapsto v$), changing a
value, and dropping or trimming a request that named something are each unsafe for some future.
\end{theorem}
\begin{proof}
\emph{If.} A blocked action is never permitted. A dropped bare request contributes nothing to later
merges (Theorem~\ref{thm:exact}(b)), so before a new request it permits nothing, and after one the
two states agree. A key marked $\conflict$ stays $\conflict$, since $\conflict$ is absorbing, and
permits nothing through that key. A key with $\st'_k = \st_k$ evolves identically. Request states
evolve identically, because they do not depend on keys, and the executions are the same events on
both sides. So whenever $s'u$ permits $o$, every key it reads carries the same value in $su$, and
$su$ permits $o$.

\emph{Only if.} For each violation, a continuation makes $s'$ permit what $s$ forbids:
\begin{itemize}
\item $\st'_k = v$ against $\st_k \in \{\bot, \conflict, v'\}$: request a reader of $k$ naming
  everything else;
\item $\st'_k = \bot$ against $\st_k = v$: first assert a fresh $w$, giving $w$ against $\conflict$;
\item $\rho'_a$ drops or changes a named value or object: a request naming a fresh value there
  leaves $s'$ unblocked and blocks $s$;
\item $\rho'_a$ invents a named value: $s'$ binds it, while $s$ reads a key that does not hold it;
\item $\rho'_a$ unblocks what $\rho_a$ blocks: any consistent request is permitted by $s'$ only.
\end{itemize}
Where the request state names the parameter to be read, one permitted execution first resets
both sides. It is permitted by $s'$, and if $s$ forbids it, that is already a violation. States
that are equivalent but differ in form (the dead states of Theorem~\ref{thm:exact}) are safe
replacements for each other, which is why the statement holds up to equivalence.
\end{proof}

In the revocable regime a key's state is a set, and forgetting needs something to write in place
of what was lost. Let memory keys also hold a \emph{mark} $\diamond$: a value that stands for
``something here was forgotten''. No retraction removes it, since nobody can name it; an expiry of
the key clears it; while present, the key never reads as a single value.

\begin{theorem}[Safe forgetting leaves a mark: revocable regime]\label{thm:safe-rev}
In the revocable regime, with memory keys that may hold $\diamond$, $s' \preceq s$ if and only if
\begin{itemize}
\item every key has $s'_k = s_k$ or $\diamond \in s'_k$;
\item every action has $\rho'_a = \rho_a$, or $\rho'_a = \mathsf{blocked}$, or ($\rho_a$ bare and
  $\rho'_a = \mathsf{absent}$).
\end{itemize}
Unlike the static regime, keys are constrained even for blocked actions, because a withdrawal can
unblock them. Without the mark, keys admit no loss at all.
\end{theorem}
\begin{proof}
\emph{If.} A key holding $\diamond$ permits nothing through it until an expiry, after which both
sides agree. The request states are handled as in Theorem~\ref{thm:safe}, and a withdrawal resets
both sides alike.

\emph{Only if.} Suppose $s'_k \neq s_k$ and $\diamond \notin s'_k$. If $s'_k$ holds a value $v$ that
$s_k$ lacks, retract everything else: $s'$ reads $v$ and $s$ reads nothing. If $s_k$ holds a value
that $s'_k$ lacks, retract everything else but some $w \in s'_k$ (or assert a fresh $w$ if
$s'_k = \emptyset$): $s'$ reads $w$, while $s$ holds two values. In either case, a withdrawal
followed by a request that names everything but the parameter on $k$ is permitted by $s'$ only.
Request states: as in Theorem~\ref{thm:safe}, after a withdrawal where needed.
\end{proof}

\begin{lemma}[One register]\label{lem:register}
A \emph{register} holds a set $S \subseteq \V \cup \{\diamond\}$. It is updated by
$\mathsf{add}(v)$, $\mathsf{retract}(v)$ for $v \in \V$, and $\mathsf{clear}$, and it is read as
$r(S) = v$ if $S = \{v\}$ with $v \in \V$, and as nothing otherwise. Call $S'$ \emph{safe for} $S$ if,
after every sequence of updates $u$, $r(S'u) = v$ implies $r(Su) = v$. Then:
\begin{enumerate}
\item[(a)] $S'$ is safe for $S$ if and only if $S' = S$ or $\diamond \in S'$;
\item[(b)] without $\mathsf{retract}$ and $\mathsf{clear}$, writing $\conflict$ for any set of two or
  more elements, $S'$ is safe for $S$ if and only if $S' = S$ or $S' = \conflict$.
\end{enumerate}
\end{lemma}
\begin{proof}
(a) \emph{If.} Updates act on $S'$ and $S$ alike. $\diamond$ survives every update but
$\mathsf{clear}$, and while it is present $r(S'u)$ is nothing. After a $\mathsf{clear}$ both sides
are empty and remain equal.

\emph{Only if.} Let $S' \neq S$ with $\diamond \notin S'$.
\begin{itemize}
\item If some $v \in S' \setminus S$, retract every other value: $r(S'u) = v$, while $Su$ is empty.
\item Otherwise $S' \subsetneq S$. Pick $x \in S \setminus S'$, and $w \in S'$ if $S'$ is non-empty,
  else add a fresh $w$ to both. Retract everything except $x$ and $w$: $r(S'u) = w$, while $Su$
  holds $x$ as well.
\end{itemize}

(b) Without retraction, sets only grow, so $\conflict$ is absorbing and reads as nothing. If
$S' = \emptyset \neq S$, add a fresh $w$: $S'$ reads $w$, $S$ holds two values. If $S' = \{v\}$ and
$S \neq S'$: $S'$ reads $v$ at once, and $S$ does not.
\end{proof}

The canonical state is a product of such registers: one per key, and one per parameter and
object slot of each action's request state, where $\mathsf{blocked}$ plays the part of $\diamond$
or $\conflict$. A permission is a conjunction of reads, and each read takes the request's named
value if there is one and the key's value otherwise. So the \emph{if} directions of
Theorems~\ref{thm:safe} and~\ref{thm:safe-rev} follow register by register:
\begin{itemize}
\item an operation permitted by $s'u$ reads, in every register it consults, a value that
  Lemma~\ref{lem:register} guarantees $su$ reads too;
\item a blocked request, or a key holding a mark, permits nothing through it.
\end{itemize}
The \emph{only if} directions need, in addition, that each register can be consulted on its own.
That is where the dead states of the static regime come from, and why the revocable regime, in
which every register can be reset and re-read, has none. Any authority semantics assembled from
registers of this kind should admit exactly the same safe losses. Stating that class precisely is
left open (Section~\ref{sec:open}).

\begin{corollary}[Forgetting a revocation is unsafe]
A memory that keeps a value the customer retracted, or a request the customer withdrew, is not a
safe replacement for the truth. The retraction case is $s'_k \supsetneq s_k$ without $\diamond$; the
withdrawal case is $\rho'_a$ present against $\rho_a = \mathsf{absent}$. A consolidator that drops the
sentence ``cancel that'' or ``not that account'' is therefore unsafe, not merely stale. This is
EAL-Bench's endogenous laundering (arXiv:2609.01836), characterised: the safe memories are exactly
those that forget only through marks.
\end{corollary}

\begin{corollary}[A safe consolidation contract]\label{cor:contract}
A consolidation step is safe, in every future, if and only if the authority state it leaves is a
safe replacement for the one it was given. By Theorems~\ref{thm:safe} and~\ref{thm:safe-rev},
Corollary~\ref{cor:dichotomy} and Theorem~\ref{thm:ceiling}, a consolidator
\begin{itemize}
\item \emph{may} drop or rewrite anything that is not the customer's own words or the books;
\item \emph{may} paraphrase, merge and reorder freely, provided the carried state is unchanged;
\item \emph{may} drop a customer's value or request only by leaving a mark: a contested key, a
  blocked action, or $\diamond$;
\item \emph{may not} resolve a conflict, drop a correction, a retraction or a withdrawal, keep a
  retracted value or a withdrawn request unmarked, or give anything a label above its source's
  ceiling.
\end{itemize}
This is checkable: it is a condition on the state carried beside the text, not on the text.
\end{corollary}

\begin{corollary}[Silent forgetting is unsafe]
A consolidator that drops a value or a correction, or keeps one of two contested values, is not
merely less useful. It is unsafe for some future. Example~\ref{ex:correction} with the correction
dropped leaves X alone in memory while the customer's state is $\conflict$, and $G$ pays X. The
gate's veto on lowered customer words (Proposition~\ref{prop:lower}) applies this theorem: demoted
words still mark the key.
\end{corollary}

\begin{corollary}[Memory under a budget]
A safe memory smaller than the canonical state must lose information through marks. Its utility
loss is the probability that a later operation needs a marked component. Under a budget, the best
safe memory marks the components least likely to be needed. Every other way of fitting the budget
is unsafe.
\end{corollary}

\paragraph{Link to the experiment.} Theorems~\ref{thm:bits} and~\ref{thm:safe} make testable
predictions about real consolidators:
\begin{itemize}
\item whether they keep the source of each value (Module~A's judge measures this);
\item whether they forget contested values and corrections silently or with a mark.
\end{itemize}
The second needs correction pairs, which the suites do not have yet.
